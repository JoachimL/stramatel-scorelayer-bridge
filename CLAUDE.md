## What this is

A single-file Python bridge (`stramatel_scorelayer_bridge.py`) that reads the serial output of a Stramatel scoreboard, parses its binary frame protocol, and PATCHes the decoded clock state to a Scorelayer HTTP API.

## Running

```bash
# Against real hardware
python stramatel_scorelayer_bridge.py --port /dev/ttyUSB0 --api-url <url> --api-token <token>

# Simulated frames (no serial port needed), print payload instead of sending
python stramatel_scorelayer_bridge.py --simulate --dry-run --verbose

# Environment variable alternatives to CLI flags
SCORELAYER_API_URL=<url> SCORELAYER_API_TOKEN=<token> python stramatel_scorelayer_bridge.py
```

## Dependencies

`requests` and `pyserial` — listed in `requirements.txt`. Install with `pip install -r requirements.txt`.

## Frame protocol

Frames are exactly 54 bytes: `START=0xF8` at byte 0, `END=0x0D` at byte 53. Key offsets:

| Offset | Content |
|--------|---------|
| 0 | START (0xF8) |
| 1 | Display code byte |
| 4–7 | Clock digits (ASCII, CP437) |
| 53 | END (0x0D) |

Clock at bytes 4–7 is decoded by `parse_clock()` into one of three modes:
- `MMSS` — four ASCII digits, e.g. `1941` → `19:41`
- `SS_TENTHS` — three digits + space, e.g. `560 ` → `00:56.0` (used under one minute)
- `UNKNOWN` / `MMSS_INVALID_SECONDS` — unparseable; `current_time_ms` will be `None`, push is skipped

## Key design decisions

- **Push on change + heartbeat**: a state is only sent to the API when it differs from the previous one, or when `--heartbeat-seconds` (default 15 s) has elapsed since the last push.
- **`current_time_ms` gating**: if the clock mode is unparseable, the PATCH is skipped entirely rather than sending a bad value.
- **`running` field is hardcoded `True`**: the Stramatel running/stopped byte has not yet been identified; update `ScorelayerClient.build_payload()` once it is.
- **Auto-resync on misalignment**: on a bad END byte, `FrameReader` seeks forward to the next `START=0xF8` byte rather than dropping just one byte (avoids thrashing when `0xF8` appears as interior frame data).
- **CP437 decoding**: the scoreboard uses Code Page 437; `decode_cp437()` is used for token extraction and raw display.
- **Heartbeat timer only advances on successful push**: `last_push_at` is not updated when `push()` returns `False`, so the API keeps getting retried on each heartbeat interval while the clock is unreadable.

## Deployment

`systemd/` contains a service unit and an install script for Raspberry Pi / Debian:

```bash
# Copy/clone the repo into /opt/stramatel-scorelayer-bridge first, then:
bash systemd/install.sh
sudo nano /etc/stramatel-scorelayer.env   # set SCORELAYER_API_TOKEN
sudo systemctl start stramatel-scorelayer
journalctl -u stramatel-scorelayer -f
```

`install.sh` creates a venv, installs `requirements.txt`, writes the env file and service unit under the running user, adds the user to the `dialout` group, and enables the service. The `systemd/stramatel-scorelayer.service` file in the repo is a reference copy; the live unit is generated by the script with paths and user substituted.
